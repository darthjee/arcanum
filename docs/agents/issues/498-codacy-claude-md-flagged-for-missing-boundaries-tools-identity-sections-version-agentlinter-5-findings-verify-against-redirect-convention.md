# Issue: Codacy: CLAUDE.md flagged for missing boundaries/tools/identity/sections/version (Agentlinter, 5 findings) — verify against redirect convention

## Description

Codacy's Agentlinter tool raises 5 findings against `CLAUDE.md`, all pointing at the file being effectively empty of agent-instruction content: it currently contains only `See [AGENTS.md](AGENTS.md) for project instructions.`

**Source:** Codacy quality issues, tool Agentlinter — 1 Warning-level + 4 Info-level findings.

**Confirmed:** this repo's `init-claude` skill deliberately generates a thin `CLAUDE.md` (and an equally thin `.github/copilot-instructions.md`) that redirects to `AGENTS.md` as the single source of truth — this is universal across every `init-claude` scenario file (`init-claude/scenario_*.md`), not specific to this repo. These findings are false positives caused by Agentlinter analyzing `CLAUDE.md` in isolation without following the redirect, similar to how prior Codacy clusters in this repo were verified rather than blindly "fixed" (see issues #460, #461, #496).

### Findings

| Pattern | Severity | Message |
|---------|----------|---------|
| `Agentlinter_completeness_has-boundaries` | Warning | No boundaries or constraints defined. The agent needs to know what NOT to do. |
| `Agentlinter_completeness_has-tools` | Info | No tool documentation found. The agent doesn't know what tools are available or how to use them. |
| `Agentlinter_structure_has-sections` | Info | Only 0 section(s) found. Use ## headings to organize instructions into clear sections (aim for 3+). |
| `Agentlinter_completeness_has-identity` | Info | No identity/persona defined. Without this, the agent has no consistent personality. |
| `Agentlinter_structure_has-version-or-update-date` | Info | No version or update date found. Helps track freshness of instructions. |

All 5 are on `CLAUDE.md:1`.

## Expected Behavior

- `.codacy.yml` gains an `exclude_paths` entry covering both `CLAUDE.md` and `.github/copilot-instructions.md`, with a comment explaining they are intentional thin redirects to `AGENTS.md` per the `init-claude` convention.
- The 5 Agentlinter findings against `CLAUDE.md` (and any equivalent findings against `copilot-instructions.md`) stop reappearing on the next Codacy analysis.
- No change to the `init-claude`-generated redirect content itself.

## Solution

Extend `.codacy.yml`'s `exclude_paths` list to add `CLAUDE.md` and `.github/copilot-instructions.md`, mirroring the existing `core/spec/support/**` entry (added for issues #460/#496):

```yaml
exclude_paths:
  - "core/spec/support/**"
  - "CLAUDE.md"
  - ".github/copilot-instructions.md"
```

Add a comment above the new entries explaining both files are intentional thin redirects to `AGENTS.md` generated by the `init-claude` skill (see `init-claude/scenario_*.md`), and that Agentlinter's per-file completeness/structure checks (boundaries, tools, identity, sections, version) don't understand the redirect and flag it as if it were a standalone, incomplete instruction file.

This is a file-based, locally verifiable exclusion — unlike a per-finding Codacy dashboard "ignore" action, which issue #461 found could not be performed in-session (no Codacy write-API/MCP credentials available) and had to be left as a manual follow-up for a human maintainer. A maintainer may still additionally mark the 5 existing findings ignored in the Codacy dashboard when convenient, but that's not required for this fix to take effect on future analyses.
