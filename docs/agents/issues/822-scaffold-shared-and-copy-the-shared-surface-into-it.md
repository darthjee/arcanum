# Issue: Scaffold shared/ and copy the shared surface into it

## Description

Part of epic #816 (extract the shared config logic into a `shared/` lib with its own agent). The design source of truth is the [Shared Lib spec](docs/agents/specs/shared-lib.md), which supersedes the epic body.

Create the `shared/` package and **copy** (not move) the consolidated surface into it, from `core/lib/shared/` (created by #820). `core/` and `cli/` are not touched. This opens the copy window that #824 closes.

## Problem

The surface now lives in `core/lib/shared/{config,file}/`, but it is still owned by `node` and tested only by core's suite. Before `core/` and `cli/` can switch to a root `shared/` folder (#824), that folder has to exist with its own package, lint, specs and coverage, and be green on its own.

## Expected Behavior

- `shared/` exists with the layout in the spec's [Layout](docs/agents/specs/shared-lib.md#layout):
  - `shared/lib/config/`: `ConfigChain.js`, `RepoConfig.js`, `RepoConfigWriter.js`, `ConfigError.js`, `AgentEmail.js`, `KeyRegistry.js`, `keys.json`;
  - `shared/lib/file/`: `Lock.js`, `LockTimeoutError.js`, `RepoPath.js`;
  - `shared/spec/{config,file}/` mirroring `lib/` 1:1, plus `shared/spec/support/`;
  - `package.json`, `yarn.lock`, `eslint.config.mjs`, `README.md`.
- The `shared/lib/` files are byte-identical copies of `core/lib/shared/` (their imports are all relative inside the folder or `node:` built-ins, so nothing needs rewriting).
- `yarn lint` and `yarn test` pass inside `shared/`, with coverage enforced.
- `core/` and `cli/` are unchanged, and their suites still pass.

## Solution

### Package

- `shared/package.json`: `"private": true`, `"type": "module"`, `engines.node` `>=22.13.0` (same floor as core), scripts `test` (`c8 jasmine`) and `lint` (`eslint .`), **no** `dependencies`, `optionalDependencies` or `peerDependencies`.
- devDependencies: `@eslint/js`, `c8`, `eslint`, `eslint-plugin-jsdoc`, `globals`, `jasmine`, **pinned to exact versions** like `cli/package.json` (`@eslint/js` 10.0.1, `c8` 12.0.0, `eslint` 10.8.1, `eslint-plugin-jsdoc` 63.3.3, `globals` 17.11.0, `jasmine` 7.0.0).
- `c8`: reporters `text` + `lcov`, exclude `spec/**` and `eslint.config.mjs`, `check-coverage: true`, with `lines`/`functions`/`branches`/`statements` set to what the copied specs reach, rounded down.
- `shared/yarn.lock`, generated by `yarn install`.
- Root `.gitignore`: add `shared/node_modules/` and `shared/coverage/`.

### Lint

`shared/eslint.config.mjs` carries core's style rules (2-space indent, single quotes, semicolons, `const`/`let`, `===`, no `console`, JSDoc on public functions; jasmine globals and no JSDoc requirement under `spec/`), plus the boundary rule on `lib/**/*.js`:

- imports only `node:` built-ins and relative paths that stay inside `shared/lib/`;
- bare built-ins (`'fs'`) rejected;
- no dynamic `import()`.

It is core's `lib/shared/**` folder rule, adapted to `shared/lib/`. Core keeps its own copy of the rule until #824.

`shared/spec/packaging/eslintBoundary_spec.js`, modelled on `cli/spec/packaging/eslintBoundary_spec.js`, lints sample code at a `shared/lib/` path with `ESLint#lintText` and asserts:

- accepted: `node:` built-ins (`node:fs/promises`, `node:path`) and relative imports inside `shared/lib/` (`./ConfigError.js`, `../file/Lock.js`);
- rejected: a bare built-in (`'fs'`), a path leaving `shared/lib/` (`../../../core/lib/context/RepoContext.js`, `../../spec/support/utils/tempDir.js`), a package import, and a dynamic `import()`.

### Specs

Follow the spec's [Spec-file inventory](docs/agents/specs/shared-lib.md#spec-file-inventory):

- **Moved** specs: copy the 9 unit specs (`AgentEmail`, `ConfigChain`, `ConfigError`, `KeyRegistry`, `keys`, `RepoConfig`, `RepoConfigWriter`, `LockTimeoutError`, `RepoPath`) from `core/spec/lib/shared/` into `shared/spec/{config,file}/`, rewriting only their import paths.
- **`Lock_spec.js`**: `shared/spec/file/Lock_spec.js` gets the unit `describe`s (`#acquire`, mutual exclusion, `#release`, stale locks, bound). The "cross-implementation race with `arcanum/_lib/lock.sh`" block is left out. Core's `Lock_spec.js` is not touched here.
- **Support**, copied into `shared/spec/support/`:
  - `utils/tempDir.js`, `utils/gitFixtureRepo.js`;
  - `fixtures/agentEmailFixtures.js`;
  - `factories/repoContextFactory.js`, **reduced** to a plain `{ repoPath }` stub (`ConfigChain` and `RepoConfig` read only `repoContext.repoPath`).
- `shared/spec` never imports from `core/spec`, `core/lib` or anything else outside `shared/`.
- Runner config `shared/spec/support/jasmine.json`: all `**/*_spec.js`, random order, **no** helpers, so `ARCANUM_STRICT_CONFIG_KEYS` is not set.

### Copies stay byte-identical

The `shared/lib/` files are not edited, not even path strings in messages. `KeyRegistry.js`'s strict-keys error still says `is not in core/lib/shared/config/keys.json`, and the copied `KeyRegistry_spec` keeps asserting that text. This keeps #824's diff check (identical apart from import paths) clean; #824 rewrites the string to `shared/lib/config/keys.json` once that path is real.

### Strict-keys guard

- The copied guard specs that pass the flag explicitly (`KeyRegistry`'s `assertRegisteredConfigKey`, `ConfigChain`, `RepoConfig`) stay as they are.
- Core's "defaults to `process.env`, which the spec runner sets" case does not hold in `shared/`. It is replaced by cases that cover the default: with `process.env` unset the guard does not throw, and with `process.env.ARCANUM_STRICT_CONFIG_KEYS` set (and restored afterwards) it throws `UNREGISTERED_KEY`.

### Zero-dependency spec

`shared/spec/packaging/package_spec.js` reads `shared/package.json` and asserts that `dependencies`, `optionalDependencies` and `peerDependencies` are absent or empty.

### README

`shared/README.md`: what the folder is (code consumed by both `core/` and `cli/`), the import boundary, how to run lint and specs, and a link to the spec. It notes the copy window and the drift rule until #824.

### Out of scope

- The compose service, Makefile targets, CircleCI jobs, Node-floor run, Codacy upload and the `shared/lib/` packaging spec (#823).
- JSCPD duplication checking, tracked in #833.
- Any change in `core/` or `cli/` (#824).
- Packaging: `shared/` ships through `EXCLUDES`/`.dockerignore` as they are, and `shared/spec/` is already excluded (#821).

### Owner

`shared`, including the two root `.gitignore` lines (agreed exception to `architect` owning root files).

### Dependencies

Items 3 (#820) and 4 (#821) of #816, both merged.

## Benefits

- `shared/`'s tooling lands and goes green before anything depends on it, so #824 is a pure prefix switch.
- Coverage and the zero-dependency rule are enforced from day one.
