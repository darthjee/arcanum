# Create the client agent file

Create `.claude/agents/client.md`, following the shape of `.claude/agents/node.md` (frontmatter, "Your scope", "Stack", "Conventions", "How to coordinate with the architect").

- **Frontmatter:** `name: client`; `description` like "Arcanum CLI specialist. Use for any task involving the user-facing `arcanum` CLI in cli/ — cli/bin/arcanum, cli/lib/, cli/spec/, cli/scripts/build.mjs, cli/package.json, cli/eslint.config.mjs, cli/README.md — plus its architecture doc and end-user guide."; `tools: Read, Edit, Write, Bash` (no `Agent`).
- **Your scope:** all of `cli/` — `cli/bin/arcanum` (including the runtime Node-version check), `cli/lib/`, `cli/spec/`, `cli/scripts/build.mjs` (the `esbuild` build with the metafile shared-surface check and the embedded per-scope migration-version list, read-only on `arcanum/migrations/repos/*/migrations.json`), `cli/package.json`, `cli/eslint.config.mjs` (including the rule restricting `core/lib` imports to the shared-surface entry files), `cli/README.md`. Also the `cli/` row in `docs/agents/folder-structure.md`, an architecture doc for the CLI's internals, and the end-user guide (e.g. `docs/guides/arcanum-cli.md`). Explicitly owned specs: `cli/package.json`'s `engines.node` equals `core/package.json`'s and the `cli/bin/arcanum` floor literal equals both; `cli/package.json`'s `version` equals `arcanum.version`; manifest shape (no runtime dependencies, no install scripts); `npm pack` contents.
- **Not owned:** `core/lib`, `core/spec` and the key registry (`node`); Docker, docker-compose, Makefile `cli-*` targets, `.circleci/`, `scripts/publish_cli_package.sh`, `scripts/bump-version.sh` (`infra`); `AGENTS.md`, the root `README.md`, the agent roster (`architect`).
- **Stack:** Node.js ESM, Yarn, Jasmine, c8, ESLint with the same style rules as `core/`; zero runtime npm dependencies (argument parsing via `node:util` `parseArgs`); `esbuild` as a devDependency for bundling.
- **Conventions** (state that this file is their source of truth): config is written only through the shared config logic, never by writing a config file directly; human-readable output by default, `--json` for scripting; specs use temp dirs as fake `CLAUDE_CONFIG_DIR`s and repos and never touch the real `~/.claude`; `child_process` only through `execFile`/`spawn` with argument arrays; never print a GitHub token.
- **Coordination:** `client` never edits `core/lib`; it requests shared-surface changes through `architect`. A PR changing a shared-surface file in `core/lib` keeps the CLI specs green in the same PR, with the plan split across `node` and `client`. CI/Docker/Makefile needs go to `infra` through `architect`. Link to `docs/agents/specs/arcanum-cli.md` for the design until #785 promotes it.
