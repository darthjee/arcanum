# Write dispatch.md

Replace the stub in `docs/agents/specs/docker/dispatch.md` with the docker branch design, precise enough for #729 to implement without further design. Header: "Part of the Docker Engine spec (epic #724). Written in #727, implemented in #729." Sections:

1. **Resolution order.** One decision table for `engine.mode=docker`, evaluated top-down:
   1. `ARCANUM_IN_DOCKER=1` → run native directly (inside the container), whatever `engine.mode` says.
   2. Command is `host-only` → native on the host.
   3. Command not docker-ready → native on the host. If there's no native implementation, the existing native → shell rule applies.
   4. Docker unavailable → native on the host.
   5. Otherwise → `docker run`.

   Each fallback prints one stderr warning (give the exact wording, in the style of today's warnings) and leaves stdout and the exit code unchanged. Also cover what `engine.mode=native`/`shell` do with the new status values: they ignore the docker flag, and `native` still means "has a native implementation".
2. **Docker-readiness source of truth (`migration-status.json`).** Define the new value shape (recommend a string enum such as `"shell"` (no native yet), `"native"`, `"docker"`, `"host-only"`, or justify an object instead). State what each value means for each `engine.mode`, how native-only commands are listed (they're absent today), and how the existing `true`/`false` values migrate. Define the reading function that replaces `_engine_dispatch_native_available`, including missing/malformed file → safest fallback. Note the other readers of the file (check `docs/agents/architecture/entrypoint-migration-status.md` and any spec or script that parses it) that #729 must update. The checklist stays hand-maintained, and ticking a row ✅ goes with flipping the value to `"docker"` in the same PR.
3. **`docker run` invocation shape.** A full annotated example assembled from `image.md`, `mounts.md` and `environment.md`: `--rm`, `-i` without `-t` (stdin passthrough, see TTY), `--user "$(id -u):$(id -g)"`, `-w "$REPO_PATH"`, the `-v` list, the `-e NAME` list, the image reference (tag resolution from `image.md`), then `arcanum <command> [<repo_path>] <args...>`. Say which pieces are per-call and which come from checklist tags. Per-call `docker run` is the default. Specify the benchmark #729 runs: which hot scripts (for example `issue-state`, `resolve-plan-paths`, `github-issue-info`), Linux and macOS, cold and warm, compared with native. Also give the threshold for moving to a long-lived container with `docker exec` (relate it to the index's "under 1s per call on Linux" target).
4. **Docker availability check.** What is checked (the `docker` binary on `PATH`, a reachable daemon, the image present locally) and with which cheap commands (for example `docker image inspect <ref>`, one call covering daemon and image). Give its cost, and decide whether results are cached within a process (no cross-call cache file unless justified). Never auto-pull, or state the pull policy from `image.md` if it says otherwise. The warning tells the user to fix Docker or change `engine.mode`.
5. **Native-only commands.** Replace today's hard error: under docker they follow the same table, using their `migration-status.json` entry.
6. **Argument path declaration.** How a shim tells dispatch which of its arguments are `args:ro`/`args:rw` paths (for example a new `--path-arg <index>:<ro|rw>` flag in the same pre-`--` segment as `--prepend-repo-path`). Cover relative vs absolute paths, paths inside the repo (no extra mount), missing files for `rw` (mount the parent), and arguments absent on a given call.
7. **Exit codes and streams.** The container exit code passes through exactly, including 3/4. stdout/stderr stay separate (no `-t`, which would merge them and add CRs). Docker's own 125 (daemon/run error), 126 (cannot invoke) and 127 (not found): decide whether to fall back to native on the host with a warning (recommended for 125 when raised before the command started) or surface them as errors. Document how "before the command started" is told apart, and that the native CLI must not use 125–127 itself (check `core/bin/arcanum` / `core/lib/core/dispatcher.js` exit codes).
8. **Nested-call guard.** Where the `ARCANUM_IN_DOCKER` check sits (first thing in `engine_dispatch`, before the mode read). Behavior for nested not-docker-ready or native-only commands inside the container: native is always available in the image, so always native. A nested command with no native implementation runs its shell script in the container, if the image allows; say so explicitly. Also cover `_engine_dispatch_run_native` forwarding the container infrastructure env (link `environment.md`).
9. **TTY.** Decided: no TTY in the container, never `-t`. TTY-owning dispatched commands (today `arcanum-create-issue-start` and `arcanum-create-issue-publish`, via `core/lib/utils/io/TtyPrompt.js`) can't open `/dev/tty`, so they take their exit-4 `FALLBACK=chat` path, which skills already handle with `AskUserQuestion`. Note the UX change (no terminal prompt under docker) and that #733 owns non-dispatched TTY scripts.
10. **Concurrency.** No `--name`, `--rm` always. Cleanup on interrupt: the dispatching process forwards SIGINT/SIGTERM (for example `docker run --init`, plus `--sig-proxy` default behavior) so no container is orphaned. Lock interplay: link `mounts.md#shared-state-and-locks`.
