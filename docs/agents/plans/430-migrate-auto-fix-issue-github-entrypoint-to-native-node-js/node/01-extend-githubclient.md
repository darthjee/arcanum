# Extend GitHubClient with PR create and ready-for-review support

`core/lib/utils/github/GitHubClient.js` currently covers `getPr`, `getPrCommits`, `mergePr`, `deleteBranch`, `getPrHeadSha`, `getCheckRuns`, and `getCurrentUser` — all REST calls bound to a single `RepoContext`. Two capabilities are missing for this migration, both genuinely new (not a re-derivation of existing native code):

- **`createPr(title, body)`**: replaces `gh pr create -R "$repo_ref" --title "$title" --body-file "$file"`. `gh pr create` infers `head` (current branch) and `base` (repo default branch) automatically; the REST endpoint (`POST /repos/{repo}/pulls`) requires both explicitly. Resolve `head` via the context-bound `Git#currentBranch()` (or `GitBranch`, whichever this class ends up depending on — mirror `PrOperations`'s constructor shape). Resolve `base` via `GET /repos/{repo}` (`.default_branch`) — `GitHubClient` has no existing method for this; add one (e.g. `getDefaultBranch()`) or fold the lookup directly into `createPr`, implementer's call. Return the created PR's `html_url` (matching `gh pr create`'s own stdout, which is the PR URL) — confirm the REST response's `html_url` field is what `gh pr create` actually prints (it is, per `gh`'s own behavior of echoing the created PR's web URL). On any non-ok response, the caller (`AutoFixIssueGithub#prCreate`) is responsible for the shell's exact `Error: could not create PR on <repo_ref>` message — `createPr` itself can throw a simpler internal error for that caller to catch and re-wrap, mirroring how `getPr`'s own `notFound()` helper is purpose-built for its one caller.

- **Mark ready for review**: replaces `gh pr ready -R "$repo_ref" "$branch"`. GitHub's REST API has no field to toggle a PR from draft to ready-for-review after creation — this requires the GraphQL mutation `markPullRequestReadyForReview(input: { pullRequestId: $id })` (verify the exact mutation/field names against GitHub's current GraphQL schema before implementing — this note is based on GitHub's documented API shape, not a value read directly from this repo). That mutation takes the PR's **GraphQL node id** (`pull.node_id` from the REST pull object), not its number. Since `GitHubClient` is REST-only today, add a small private GraphQL helper (`POST https://api.github.com/graphql` with `Authorization: Bearer <token>` and `{ query, variables }` as the JSON body) and a public method (e.g. `markPrReady(nodeId)`) built on it. Scope this helper narrowly to this one call — don't build a general-purpose GraphQL client beyond what `pr-ready` needs.

Add JSDoc for both new methods matching the file's existing style (see `getPr`'s doc comment for the level of detail expected: parameters, return shape, thrown-error message text).
