# Plan: Codacy: CLAUDE.md flagged for missing boundaries/tools/identity/sections/version (Agentlinter, 5 findings) — verify against redirect convention

Issue: [498-codacy-claude-md-flagged-for-missing-boundaries-tools-identity-sections-version-agentlinter-5-findings-verify-against-redirect-convention.md](../../issues/498-codacy-claude-md-flagged-for-missing-boundaries-tools-identity-sections-version-agentlinter-5-findings-verify-against-redirect-convention.md)

## Overview

Codacy's Agentlinter tool raises 5 findings against `CLAUDE.md`, all stemming from the file being a deliberate 1-line redirect to `AGENTS.md` (`See [AGENTS.md](AGENTS.md) for project instructions.`) rather than a self-contained agent-instruction file. This is confirmed intentional and universal — every `init-claude/scenario_*.md` generates `CLAUDE.md` (and `.github/copilot-instructions.md`) this way. The fix is a file-based Codacy exclusion, not a content change.

## Context

- This repo already has a precedent for exactly this kind of false positive: `.codacy.yml`'s `exclude_paths` currently excludes `core/spec/support/**` (added for issues #460/#496), with an explanatory comment.
- A different precedent (issue #461) tried suppressing via per-finding Codacy dashboard "ignore" actions and inline code comments, but could not actually mark findings ignored in-session (no Codacy write-API/MCP credentials available) — that had to be left as a manual follow-up for a human maintainer.
- `.github/copilot-instructions.md` carries the identical 1-line redirect pattern and would plausibly trip the same Agentlinter completeness/structure checks, so it's covered proactively alongside `CLAUDE.md`.
- No `.claude/agents/` specialist in this repo matches editing a root-level `.codacy.yml` (not Docker/Makefile, not `core/`'s Node source, not skill scripts) — this is `architect` scope per its own description ("root-level files").

## Implementation Steps

### Step 1 — Extend `.codacy.yml`'s `exclude_paths`

Add `CLAUDE.md` and `.github/copilot-instructions.md` to the existing `exclude_paths` list in `.codacy.yml`, with a comment (mirroring the style of the existing `core/spec/support/**` comment) explaining both files are intentional thin redirects to `AGENTS.md` generated by the `init-claude` skill, and that Agentlinter's per-file completeness/structure checks (boundaries, tools, identity, sections, version) can't see past the redirect. Reference issue #498 in the comment.

## Files to Change

- `.codacy.yml` — add `CLAUDE.md` and `.github/copilot-instructions.md` to `exclude_paths`, with an explanatory comment referencing issue #498.

## Notes

- No change to `CLAUDE.md`, `.github/copilot-instructions.md`, or the `init-claude` skill's generated redirect content.
- The 5 existing findings against `CLAUDE.md` may still show as open in Codacy's dashboard until its next analysis run re-scans the repo against the updated `exclude_paths`; no local verification command exists for this (Codacy-side exclusion, not a local linter config).
- A human maintainer may additionally mark the 5 existing findings ignored in the Codacy dashboard when convenient, but that's not required for the exclusion to take effect on future analyses.
