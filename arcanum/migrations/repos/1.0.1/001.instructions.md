# Migration 001 Instructions — Warn About shell engine.mode Removal

Tell the user that `engine.mode=shell` is deprecated and offer to set
`engine.mode` in the **global** arcanum config. This migration is
`global`-scoped: it is shown once per machine/account, and it only ever
writes the global tier. Never edit the repo or local tier yourself.

1. Resolve the current `engine.mode` per tier, reading `.engine.mode`
   with `jq` from each file that exists (a missing file or key means
   "not set" for that tier):
   - local: `.claude/state/arcanum-config.json` (in the target repo)
   - repo: `.claude/configuration/arcanum-repo-config.json` (in the
     target repo)
   - global: `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/arcanum-config.json`

   The effective value is the first one set, in the order local → repo
   → global. If none is set, the effective value is `shell` (the
   absent-key default). Report the effective value and which tier it
   comes from.

2. If the effective value is already `native` or `docker`, tell the
   user nothing is needed and finish without making changes.

3. Check whether `node` is available (`command -v node`), and whether
   `docker` is available (`command -v docker`). Docker availability is
   for information only.

4. Explain that the `shell` engine will be removed in a future arcanum
   release, then offer three choices:
   - **native** — recommended when Node.js is available. If `node` is
     not on PATH, warn the user that native mode needs Node.js and
     would fall back to shell until it is installed.
   - **docker** — note that today `engine.mode=docker` still falls
     back to shell with a warning (see `arcanum/_lib/engine_dispatch.sh`);
     it becomes effective once docker mode is implemented.
   - **decide later** — change nothing now.

5. For **native** or **docker**, write the value to the global tier
   using the sanctioned helper, never by editing the JSON by hand.
   `global_config.sh` lives in the arcanum install at
   `arcanum/_lib/global_config.sh` — i.e. `../../../_lib/global_config.sh`
   relative to this instructions file. For example, for native:

   ```bash
   bash -c 'source <arcanum>/_lib/global_config.sh && global_config_write "<repo_path>" engine mode "\"native\""'
   ```

   (use `"\"docker\""` for docker). Afterwards, confirm the global file
   contains `{"engine":{"mode":"<choice>"}}`. Then, if step 1 found
   `engine.mode` explicitly set in the local or repo tier, tell the
   user that tier still takes precedence over the global value, and
   name the file they need to change. Do not edit it yourself.

6. For **decide later**, change nothing. Restate that when shell is
   removed, arcanum will pick an engine automatically: `native` if
   Node.js is available, otherwise `docker` if Docker is available,
   otherwise a hard error asking the user to install Node.js
   (preferred) or Docker.

7. Tell the user this migration is shown only once per machine/account:
   the global migration pointer advances whichever choice they make, so
   it will not be shown again in this or any other repo.
