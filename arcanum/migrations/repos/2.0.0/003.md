# Migration 003 (next) — turn on auto-next for your account

Sets the `next_step.auto.<skill>` keys on the global, cross-project
config file (`${CLAUDE_CONFIG_DIR:-$HOME/.claude}/arcanum-config.json`,
see [the global config guide](../../../../docs/guides/arcanum-global-config.md)),
the outermost tier of the chain — the fallback every repo you touch uses
when neither its local per-clone setting (migration 001) nor its
repo-wide setting (migration 002) sets the key. Same three skills, in
the same order, as migration 001 — `enhance-issue`, `discuss-issue` and
`auto-plan-issue`; see 001.md for the offer each one skips when its key
is `true`.

The migration explains up front that an explicit `false` shadows a
`true` set in a lower-precedence tier (local → repo → global), so a
`false` in the local or repo tier still wins over a `true` set here.

Applies machine/account-wide, across every repo the active Claude Code
account/profile touches — not committed to any repo. Same interactive
shape as migrations 001/002: `[Y]es/[N]o/[S]kip` once per skill, `Y`
writes `true`, `N` writes `false`, and anything else writes nothing.
Silently does nothing when no interactive terminal is available. If the
global config location can't be resolved (no `$HOME`/
`$CLAUDE_CONFIG_DIR`), the underlying write degrades silently on its
own.

Safe to re-run — global, cross-project state (`applies_to: "global"`),
so re-running only matters if you want to change your account-wide
default later.
