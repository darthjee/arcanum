# Migration 001 (next) — create the `Epic` label on this repo

Creates the `Epic:fbca04` label on this repo's live GitHub labels
(`gh label create`) if it is missing. `Epic` is a new init-claude
default label and a non-actionable pipeline tag (`epic`): `mark-split`
(called by `arcanum-split-issue`'s finish step) adds it to a split
parent, and label carryover strips it from sub-issues/spawned issues
(issue #689).

Existing labels are matched case-insensitively (GitHub label names are
unique case-insensitively). If an `Epic` label already exists, it is
left untouched — this migration never edits a label's name or color.

Adding a label is fully additive/reversible, so there is no `/dev/tty`
confirmation prompt; it runs silently in both interactive and
non-interactive contexts, printing one informational line.

This migration applies once per repo (the GitHub labels are shared by
every checkout). The matching `.claude/state/init-claude-config.json`
update is a separate, per-checkout migration (`002`), because that file
is git-ignored and each checkout has its own copy.

Skipping it is harmless in the short term: `mark-split`'s `epic`
mutation is best-effort, so splitting still works, the parent just
won't get the `Epic` label. Safe to re-run — idempotent.
