# Migration 001 (next) — set your global, cross-project commit email default

Sets the `git.email` key on your new, global, per-account
`${CLAUDE_CONFIG_DIR:-$HOME/.claude}/arcanum-config.json` — the
outermost tier of arcanum's config resolution chain (local repo state
-> repo config -> global user config -> hardcoded default), consulted
by `agent_email_get` only when neither the current repo's local state
nor its repo config already has a `git.email` value.

**Same per-agent *template* rule as 0.14.0/002.sh's per-repo prompt.**
It must contain the literal substring `{agent}`, replaced with the
actual agent name (`architect`, `backend`, `frontend`, ...) at commit
time.

This migration checks the same chain before prompting: if the current
repo already has `git.email` set locally or in its repo config (e.g.
because `0.14.0/002.sh` already ran here), or if some other repo on
this machine/account has already written the global default, it
silently does nothing — no prompt, nothing to answer twice. Only when
none of the three tiers has anything yet does it guess a default from
your `git config user.email` (same derivation as `002.sh`) and, when an
interactive terminal is available, offer to confirm the guess, type a
different pattern, or skip. When no interactive terminal is available,
the guessed default (if any) is written silently, no prompt.

Net effect: you answer this at most once, ever, across every repo on
this machine/account — the first repo whose local state and repo
config are both still empty when this migration reaches it. Every
other repo's copy of the same migration then finds the global value
already set and no-ops.

Safe to re-run (`applies_to: "local"`, so it re-runs on every clone) —
idempotent, since it only ever writes when nothing is configured
anywhere yet.
