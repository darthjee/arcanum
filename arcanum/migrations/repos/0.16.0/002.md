# Migration 002 (next) — seed the shipit-merge permission exemption (repo)

Grants the same single, narrowly-scoped Bash-permission allowlist
entry as migration 001 —
`Bash(auto-fix-all/scripts/wait_ci_and_merge.sh *)` — but in the
shared, committed `.claude/settings.json` instead, visible to every
contributor of this repo.

`wait_ci_and_merge.sh` is the dedicated script `auto-fix-all` calls
*only* on the `shipit`-preapproved merge path (see issue #170): it
waits for CI, then merges the PR internally. The normal, human-review-
approved merge path calls a different, separate Bash invocation
(`scripts/github.sh pr-merge`), which stays unaffected and still hits
Claude Code's permission classifier — this migration does not touch
it. See `docs/agents/architecture/issue-tags.md`'s `shipit` paragraph
for the full rationale.

**This value gets committed to the repo and is visible to every
contributor** — you'll see an explicit warning to that effect before
being asked to confirm/skip (`applies_to: "repo"`). See migration 001
for the equivalent, clone-local-only grant, and 003 for the equivalent
grant across every arcanum-onboarded repo on this machine/account.

Skipping this migration is harmless: `auto-fix-all` still works end to
end, it will just stop at the merge step for `shipit`-preapproved
issues and ask for confirmation, exactly like today, for any
contributor who hasn't separately granted it themselves (e.g. via
migration 001). Safe to re-run — the grant is deduped, not appended
twice.
