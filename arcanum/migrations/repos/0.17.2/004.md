# Migration 004 (next) — seed the specialist-dispatch commit/check permission bundle (global)

Grants the same bundle of three narrowly-scoped Bash-permission
allowlist entries as migrations 002/003 — but in Claude Code's own
cross-project `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/settings.json`
instead, so it applies across every arcanum-onboarded repo on this
machine/account (`applies_to: "global"`), not just this one (see
issue #205):

- `Bash(auto-fix-issue/scripts/commit_change.sh *)` — every dispatched
  specialist's own commit+push path.
- `Bash(auto-fix-issue/scripts/run_checks.sh *)` — every dispatched
  specialist's own test/lint runner.
- `Bash(git add *)` — the raw staging call each dispatched specialist
  runs immediately before `commit_change.sh`.

This is Claude Code's own native global settings file — distinct from
arcanum's own `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/arcanum-config.json`
that lives in the same directory (see `arcanum/_lib/global_config.sh`).
Only the former is actually read by Claude Code's permission
classifier, which is why this migration writes there instead.

These three are the common, fixed, narrow instructions every dispatch
relies on regardless of domain (`auto-fix-issue/steps/dispatch_agents.md`
and `auto-fix-all/steps/handle_comment.md`'s "Dispatching" section);
they do not cover any specialist's own ad hoc implementation commands
(e.g. `docker`, `yarn test`), which stay unaffected and still hit the
classifier or #200's `OUTCOME=blocked` escalation path on every repo.
See `docs/agents/architecture/dispatch-permissions.md` for the full
audit and rationale, and `docs/agents/architecture/issue-tags.md`'s
`shipit` paragraph for the precedent this generalizes.

Skipping this migration is harmless: dispatched specialists still work
end to end on every repo, they will just keep hitting the classifier
(or, in headless/non-interactive contexts, #200's `OUTCOME=blocked`
escalation path) at their commit/check/staging steps, exactly like
today, unless a given repo already has the grant via migration 002 or
003. Safe to re-run — each grant is deduped, not appended twice.
