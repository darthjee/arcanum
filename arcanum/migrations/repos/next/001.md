# Migration 001 (next) — delete the legacy `auto-fix-all.json` and `monitor-issues.json`

Deletes `.claude/configuration/auto-fix-all.json` and
`.claude/configuration/monitor-issues.json`, after first seeding the
`auto-fix-all` namespace of `.claude/configuration/arcanum-repo-config.json`
from the legacy `auto-fix-all.json` (only if that namespace is missing).

Why: since #902–#904, no reader or writer touches these files any more —
there is no read fallback, no seed on write and no warning. They are inert
leftovers, and this migration cleans them up.

Why it seeds first: a repo that never ran `0.9.3/001` or `0.18.0/001` may
still hold its only copy of the `auto-fix-all` values in the legacy file.
Seeding before deleting means such a repo loses nothing. If the legacy
file is invalid JSON, the seed fails and the migration stops before
deleting anything.

Why a legacy file that disagrees with the namespaced value is safe to
delete: when the `auto-fix-all` namespace already exists, seeding is a
no-op, and the namespaced value is the one every reader already uses — the
legacy value was already being ignored.

Why it is skippable: nothing reads these files, so a repo that declines
this migration simply keeps two inert files around.

The deletion shows up as an uncommitted change in the repo (along with any
seeded `arcanum-repo-config.json`); commit it yourself.

Safe to re-run: seeding is a no-op once the namespace exists or the legacy
file is gone, and `rm -f` on an already-deleted file does nothing.
