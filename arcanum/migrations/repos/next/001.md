# Migration 001 (next) — sync the `Spawned` label to this repo

Creates or updates the `Spawned:6a737d` label directly on this repo's
live GitHub labels (`gh label create`/`gh label edit`, matching
`init-claude/scripts/sync_labels.sh`'s existing case-insensitive-
match-then-create-or-update logic) — this is what actually makes
`arcanum/_lib/spawn_issue.sh`'s `gh issue edit --add-label Spawned`
succeed (see issue #174).

If this repo already ran `init-claude`'s label setup
(`.claude/state/init-claude-config.json` exists), also upserts
`Spawned:6a737d` into that config via
`init-claude/scripts/write_label_config.sh add`, so a future manual
`sync_labels.sh` re-run stays consistent. If the config doesn't exist,
that part is simply skipped.

Unlike the shipit-permission migrations, this does not loosen any
security gate — adding a label is fully additive/reversible — so
there's no `/dev/tty` confirmation prompt. It runs silently in both
interactive and non-interactive contexts, printing an informational
line either way.

Skipping this migration is harmless in the short term, but any issue
spawned via `spawn_issue.sh`/`arcanum-split-issue` on this repo before
it's applied will fail to get the `Spawned` label applied (best-effort
— the issue itself still gets created). Safe to re-run — creating or
updating the label is idempotent.
