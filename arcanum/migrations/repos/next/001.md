# Migration 001 (next) — turn on auto-next for this clone

Sets the `next_step.auto.<skill>` keys on your local, per-clone
`.claude/state/arcanum-config.json`, for `enhance-issue`,
`discuss-issue` and `auto-plan-issue`, in that order. When a skill's key
is `true`, it skips its next-step offer and runs the offered command
directly, as a chained run:

- `enhance-issue` — skips the `/discuss-issue <id>` offer. Never applies
  to an Epic.
- `discuss-issue` — skips the `/auto-plan-issue <id>` offer.
- `auto-plan-issue` — skips the `/loop /auto-resolve-issue <id>` offer
  once a plan exists.

This is the local tier, the highest precedence in the chain
(local → repo → global). An explicit `false` here shadows a `true` set
in the repo tier (migration 002) or the global tier (migration 003);
the migration explains this before the first prompt.

When an interactive terminal is available, you're prompted
`[Y]es/[N]o/[S]kip` once per skill. `Y` writes `true`, `N` writes
`false`, and anything else writes nothing, leaving the key unset so
lower tiers (or the default: always offer) still apply. When no
interactive terminal is available (e.g. automated/CI-style runs), the
migration silently does nothing.

Safe to re-run — local, per-clone state (`applies_to: "local"`), so it
re-prompts on every clone/run, and each answer only overwrites that
skill's key.
