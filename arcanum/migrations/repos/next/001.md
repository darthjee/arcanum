# Migration 001 (next) — seed the local `monitor-issues` namespace

Copies the content of the legacy, per-clone
`.claude/state/monitor-issues-config.json` (where `monitor-issues` kept
its `clear_context` toggle) into `.claude/state/arcanum-config.json`,
under the `monitor-issues` namespace key — e.g.
`{"clear_context": true}` becomes
`{"monitor-issues": {"clear_context": true}}`, alongside any other
namespaces already in that file.

This is a local migration (`applies_to: "local"`): both files are
gitignored, per-clone state, so it runs once per clone rather than once
per repo.

Why it isn't skippable: `monitor-issues` now reads and writes
`clear_context` only from `.monitor-issues.clear_context` in
`.claude/state/arcanum-config.json`, with no read-time fallback to the
legacy file. Without this migration, an existing `clear_context` value
would silently reset to `false`.

Safe to re-run: if the `monitor-issues` key already exists in
`.claude/state/arcanum-config.json`, or the legacy file doesn't exist,
seeding is a no-op.

Nothing is deleted: the legacy `.claude/state/monitor-issues-config.json`
and the old `.claude/state/monitor-issues-config.lock` are left in place
(they are no longer read, and can be removed by hand).
