# Migration 003 Instructions — Add the Specs Concern to the Split Checklist

Add the **Specs** concern to the target repo's
`docs/agents/arcanum-split-issue.md` checklist, mirroring what
`/init-claude` now seeds for newly initialized repos.

1. Check whether `docs/agents/arcanum-split-issue.md` exists at the
   target repo root. If it does not exist, there is nothing to do —
   mark this entry complete without making any changes.

2. Read the file. If it already has a concern about specs, or about
   designs that must be agreed before splitting (any wording), make no
   changes.

3. If the file has no recognisable concern list (e.g. it has been
   rewritten as prose or restructured beyond recognition), ask the user
   where — or whether — to add the concern rather than guessing.

4. Otherwise, append the bullet quoted in [The Specs bullet](#the-specs-bullet)
   below as the last item of the concern list. If the existing items use
   a different shape (e.g. plain bullets without a bold label, or a
   numbered list), express the same concern in that shape instead of
   forcing the bullet in verbatim.

5. Never reword, reorder or remove existing items, and never touch
   anything else in the file. Save the file.

This migration only ever touches `docs/agents/arcanum-split-issue.md`.

## The Specs bullet

The exact line `/init-claude` seeds, byte for byte:

```markdown
- **Specs** — does any part of this work need a design agreed in `docs/agents/specs/` first (worth its own "write the spec" sub-issue), and do existing specs listed in `docs/agents/specs.md` constrain how the sub-issues are shaped?
```
