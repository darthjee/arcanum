# Migration 003 (next) — seed the shipit-merge permission exemption (global)

Grants the same single, narrowly-scoped Bash-permission allowlist
entry as migrations 001/002 —
`Bash(auto-fix-all/scripts/wait_ci_and_merge.sh *)` — but in Claude
Code's own cross-project `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/settings.json`
instead, so it applies across every arcanum-onboarded repo on this
machine/account (`applies_to: "global"`), not just this one.

This is Claude Code's own native global settings file — distinct from
arcanum's own `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/arcanum-config.json`
that lives in the same directory (see `arcanum/_lib/global_config.sh`).
Only the former is actually read by Claude Code's permission
classifier, which is why this migration writes there instead.

`wait_ci_and_merge.sh` is the dedicated script `auto-fix-all` calls
*only* on the `shipit`-preapproved merge path (see issue #170): it
waits for CI, then merges the PR internally. The normal, human-review-
approved merge path calls a different, separate Bash invocation
(`scripts/github.sh pr-merge`), which stays unaffected and still hits
the classifier on every repo — this migration does not touch it. See
`docs/agents/architecture/issue-tags.md`'s `shipit` paragraph for the
full rationale.

Skipping this migration is harmless: `auto-fix-all` still works end to
end on every repo, it will just stop at the merge step for `shipit`-
preapproved issues and ask for confirmation, exactly like today,
unless a given repo already has the grant via migration 001 or 002.
Safe to re-run — the grant is deduped, not appended twice.
