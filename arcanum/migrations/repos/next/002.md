# Migration 002 (next) — turn on auto-next for the whole repo

Sets the `next_step.auto.<skill>` keys on the shared, committed
`.claude/configuration/arcanum-repo-config.json`, as the repo-wide
default every contributor falls back to when they haven't set their own
value via migration 001. Same three skills, in the same order, as
migration 001 — `enhance-issue`, `discuss-issue` and `auto-plan-issue`;
see 001.md for the offer each one skips when its key is `true`.

This is the repo tier, in the middle of the chain
(local → repo → global). A contributor's local value (migration 001)
always wins over this one, and an explicit `false` here shadows a
`true` set in the global tier (migration 003); the migration explains
this before the first prompt.

**These values get committed to the repo and are visible to every
contributor** — you'll see an explicit warning to that effect first.
Same interactive shape as migration 001 otherwise: `[Y]es/[N]o/[S]kip`
once per skill, `Y` writes `true`, `N` writes `false`, and anything
else writes nothing. Silently does nothing when no interactive terminal
is available.

Safe to re-run — repo-wide, committed state (`applies_to: "repo"`), so
re-running only matters if you want to change the shared default later.
