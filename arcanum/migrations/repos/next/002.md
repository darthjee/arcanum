# Migration 002 (next) — seed the global migrations version pointer

No-op migration, `applies_to: "global"`. Its sole purpose is to
initialize `.migrations.version` in the global, cross-project config
file (`${CLAUDE_CONFIG_DIR:-$HOME/.claude}/arcanum-config.json`, see
[the global config guide](../../../../docs/guides/arcanum-global-config.md))
for every install, now that `"global"` exists as a real `applies_to`
scope alongside `"repo"`/`"local"` (see
[the per-repo migrations architecture doc](../../../../docs/agents/architecture/per-repo-migrations.md)).

It has no other effect — `run` does nothing but exit successfully.
Safe to re-run, and safe to skip: skipping it just means the global
pointer doesn't advance yet and it's offered again next run, same as
any other skipped entry. Ships alongside the plumbing that adds the
`"global"` scope, to prove the new pointer resolution, hard-error path,
lock, and `_advance_pointers` arm work end-to-end on real installs
before any consequential `"global"`-scoped migration depends on it.
