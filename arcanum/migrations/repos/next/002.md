# Migration 002 (next) — set your personal per-agent commit email

Sets the `git.email` key on your local, per-clone
`.claude/state/arcanum-config.json`, used by `commit_change.sh`/
`commit_issue.sh`/`commit_plan.sh` (once migration 001 has also been
applied) to fill in the email on each commit's "agent"
`Co-Authored-By` line.

**Important — `git.email` holds a per-agent *template*, not a static
address.** It must contain the literal substring `{agent}`, which gets
replaced with the actual agent name (`architect`, `backend`, `frontend`,
...) at commit time — so each agent ends up with its own distinct
email, all derived from the one pattern you set here. For example,
setting it to `you+{agent}@example.com` makes the `architect` agent's
commits show `you+architect@example.com`, `backend`'s show
`you+backend@example.com`, and so on. Registering each generated
address as a verified email on its own GitHub account (for per-agent
attribution) is your responsibility, not this migration's.

Guesses a default from your `git config user.email` (e.g.
`darthjee@gmail.com` → `darthjee+{agent}@gmail.com`) and, when an
interactive terminal is available, offers to confirm the guess, type a
different pattern, or skip. If `git config user.email` is empty there
is no guess to offer — you're prompted to type a pattern or skip
instead. Skipping leaves the key unset, which simply means every
agent's commits keep reusing the AI model's own email on the agent
line too (today's behavior, unchanged). When no interactive terminal is
available, the guessed default (if any) is written silently, no
prompt.

Safe to re-run — local, per-clone state (`applies_to: "local"`), so it
re-prompts (or re-applies the guess) on every clone/run.
